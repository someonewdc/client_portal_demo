# Scope продукта

## Два зрителя

1. **Заказчик завода** (пользователь страницы): открыл ссылку из мессенджера.
   Логина нет. За 30 секунд: заявка жива; шаг принят → в расчёте → КП → счёт;
   можно открыть файл-выписку. Фраза: «вот что видит мой клиент, пока мы считаем».
2. **Покупатель Protostar** (владелец / коммерческий / РОП): смотрит ту же
   страницу как артефакт к письму или как поставку v1. Не путать с посетителем
   лендинга `protostar.ru`.

Не оператор ERP, не оптовый закупщик в каталоге, не ведущий театра Нордщита.

## Что в v1

- Одна заявка по секрету в URL: `/r/{secret}`.
- Этапы линейной лентой, штампы, дата обновления.
- Краткая спецификация (2–5 строк состава, не корзина SKU).
- Файлы списком метаданных; имя открывает HTML-лист `/r/{secret}/d/{fileName}`,
  без download бинаря.
- Несуществующий секрет → тупик, не форма входа.
- Индекс `/` не является кабинетом заказчика: короткая заглушка «откройте ссылку
  от менеджера», без каталога заявок.
- Как менеджер **создаёт и двигает** заявку — D-008 (CLI / узкий operator HTTP).
  Экрана пульта показа и списка «для зрителя Protostar» нет.

## Сейчас в репозитории (после генератора `--preset portal`)

Ядро `@protostar/*`, Nest health, `GET /requests/{accessSecret}`, Nuxt-кабинет и
лист файла, seed no-op, индекс-заглушка. Театра Нордщита нет. Заявок в БД нет.

## In

- Канал статуса одной не‑SKU заявки.
- Секрет в URL как capability, не пользователь.
- Документный русский UI.
- Один пример заявки как артефакт к продаже (задача 1), пока нет платящего.
- Стенд на `:3100` / `:3101` / `:5434`.

## Связь с сайтом

Лендинг обещает «страницу заявки, которую можно отдать клиенту». Этот git — та
страница. Сайт не встраивает её iframe'ом в hero. Ссылку на живой hostname
добавляют в Astro только после HTTP 200 (как `demoUrl` для Вольтариса).
