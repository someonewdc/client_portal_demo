# Frontend

Интерфейс на русском. Два экрана, один layout. Не витрина, не дашборд.

## Что запрещаем (нейрослоп и соседние соблазны)

Glassmorphism, градиентные стеклянные карточки, bento-сетка, неон, 3D-блобы, тёмная
«кибер» тема, стоковые иллюстрации «AI dashboard», канбан, графики KPI, hero-баннер
магазина, бесконечный UI-kit.

## Токены

Одна гарнитура: **IBM Plex Sans** (кириллица) + `font-variant-numeric: tabular-nums` для
номеров заявок и дат. Грузить пакет `@fontsource/ibm-plex-sans`, не Google Fonts CDN
(D-015). Не Inter как «дефолт SaaS», не декоративный serif.

Предлагаемые значения для `@theme` (фича 4 фиксирует в CSS, **подключённом** из layout
или `nuxt.config`; мёртвый файл с переменными не считается. Не копирует токены Вольтариса):

- бумага: `--color-paper: #f4f1ea`
- поверхность листа: `--color-sheet: #fffcf7`
- чернила: `--color-ink: #1c1917`
- вторичный текст: `--color-ink-muted: #5c564e`
- акцент (пыльная сталь / синий): `--color-accent: #3d5a73`
- линия: `--color-rule: #d6d0c4`
- штамп текущий: чернила на плашке `--color-rule` (NHS tag, не акцент ссылки; D-045)
- штамп пройден: чернила, без кричащего фона
- штамп будущий: muted

Много воздуха: узкая колонка документа (~40–42rem), крупные поля.

Абзацы экранов ниже — **целевое** состояние после UX-задач 1–18 (D-036…D-045).
Вход 1–12: `выполни ux задачу N`. Вход 13–18: `реализуй ux задачу N` (цикл).
До merge 1–12 в `main` живой стенд — фичи 10–13: бренд в шапке как `h1`,
смысловой заголовок кабинета = номер (`h2`), без подписей полей и фразы «что
дальше», один текст 404, на тупике виден `Код ошибки`. Фичи 15–27 не подгоняют
вёрстку под абзацы ниже и не переписывают текст тупика, пока нужная UX-задача
не в `main`.

Иерархия кабинета после UX-нарезки (D-027, D-037): `Статус заявки` → **текущий
`stage.label` (h1)** → номер (не heading) → фраза про ссылку → подписи
`Заказчик` / `Изделие` / `Обновлено` (дата **без** штампа) → фраза «что дальше» →
лента 1–4 → спецификация → файлы.

## Экран 1 — индекс демо-ссылок (`/`)

Служебный. Заголовок `Ссылки для показа`. Затем дословно: этот список не показывается
заказчику; «Так выглядит то, что вы отправили бы заказчику в мессенджер.» Инструкция:
«Нажмите строку — откроется экран заказчика по ссылке.»

`h1` и title: `Ссылки для показа` / `Ссылки для показа — ПК «Нордщит»` (D-040).

Список из API (`GET /demo/links`): номер, контрагент, статус-штамп, дата. Каждая строка —
настоящая ссылка на `portalPath` (номер и title — `.document-link`: акцент,
линия 2px с отступом 3px и лёгкая плашка по строкам, не рамка и не `--color-rule`;
D-043, D-044). Штамп — `.status-stamp`: чернила на `--color-rule`, weight 400,
`cursor: default` (выглядит ненажимаемым, даже внутри строки-ссылки), не
акцент и не ссылочный текст (D-040, D-045). Нет кнопки «скопировать», нет `#`. После
фичи 25 ссылка — `NuxtLink` (D-034), только после фичи 16 в `main`; фича 16 `<a href>`
не меняет. UX-задачи тип ссылки не меняют.

Состояния: loading / error (`traceId`, HTML-статус = код API после фичи 17) / empty
(разметка остаётся; предназначенный стенд после D-031/F18 не отдаёт пустой 200).

## Экран 2 — кабинет (`/r/{accessSecret}`)

Шапка layout: текст `ПК «Нордщит»`, не heading (D-040). На листе (D-037): подпись
`Статус заявки`, `h1` = текущий `stage.label`, номер tabular, фраза
`Менеджер отправил вам эту ссылку. Вход не нужен.`, поля `Заказчик` / `Изделие` /
`Обновлено` без штампа у даты, фраза «что дальше» по статусу. Title:
`{statusLabel} — {publicNumber} — ПК «Нордщит»`. Лента 1–4: пройденные с `reachedAt`,
текущий — тот же `.status-stamp`, что на индексе (чернила на `--color-rule`,
выглядит ненажимаемым) + `aria-current="step"` + `sr-only` `сейчас`, будущие — muted
и `ещё нет` (D-038). На `< 40rem` пункт ленты — колонка; от `40rem` три общие
колонки счётчик / штамп / дата (даты в одном X, D-043). Спека — блоки с подписями
колонок на узкой ширине, без горизонтального скролла страницы. Desktop-таблица от
`40rem`; «Кол-во» в `thead` в одну строку; колонка «Комментарий» только если у
строки есть `comment`. Файлы — записи; под заголовком
`Имя файла открывает выписку на экране.` (D-039). Одна сетка на все строки (D-043).
Кликабельно только имя: `/r/{accessSecret}/d/{fileName}` (D-029), класс
`.document-link` (начертание D-044); после фичи 25 — `NuxtLink` (D-034).

Лист (D-039): тип, `h1` = `fileName`, номер, `Заказчик` / `Изделие` / `Загружено` /
`Размер`, дисклеймер `Это выписка на экране, а не файл для скачивания.`, зачин D-029,
спека той же схемой, что кабинет (таблица от `40rem`, блоки ниже), не inline
`ml-*`; `К заявке {publicNumber}` — `.document-link` (начертание D-044, декоративная `←`). Title:
`{kindLabel} — {publicNumber} — ПК «Нордщит»`. Нет кнопки «скачать», `[download]`,
`href="#"` (D-009).

404 (D-039): h1 `Ссылка недействительна`, title
`Ссылка недействительна — ПК «Нордщит»`, без формы входа, телефона, OTP, без
`Код ошибки` на 404. Неизвестный секрет: `Заявки по этой ссылке нет. Проверьте адрес
или попросите новую ссылку у менеджера.` Имя не из `files` при живой заявке:
`Такого документа в заявке нет. Откройте заявку и выберите документ из списка.` +
`К заявке {publicNumber}`. Ссылки с кабинета на индекс `/` нет.

`:focus-visible` — кольцо акцента 2px (D-040). Ссылки документа в покое —
`.document-link` (D-043, начертание D-044).

Нет чата, логина, корзины, графиков.
