# План UX/UI (понятность, self-explained)

Вход оператора. Код здесь не пишут. Каждая задача — отдельный чат, одна
feature-ветка, один PR в `main` по `docs/ux/task-NN.md`.

Это **не** скоуп фич 15–27 и **не** `docs/llm/feature-NN.md`. Дефекты API/стенда
по-прежнему: [`../remediation-plan.md`](../remediation-plan.md)
(`выполни задачу N`, без `ux`).

## Как запускать

Задачи 1–12 (уже в поставке или на финише) — один чат, агент пишет сам:

```text
выполни ux задачу N
```

Задачи 13–18 (сетка и ссылки в покое) — полный вход **и** цикл
implement → review. В новом чате достаточно:

```text
реализуй ux задачу N
```

`N` — номер из колонки «Задача» ниже. Больше ничего не добавляй: не скармливай
прошлый анализ и не пиши «через implement → review». Родитель открывает skill
`implement-review-cycle`, код пишет `plan-item-implementer`, ревью —
`plan-diff-reviewer` (D-042).

Фраза `выполни задачу N` / `реализуй задачу N` без слова `ux` — **не** этот
каталог, а [`../remediation-plan.md`](../remediation-plan.md) (фичи 15–27).

`выполни ux задачу N через implement → review` по-прежнему включает цикл для
любого номера. Голые «следующий пункт» и «суперагент» цикл не включают.

Задачу 0 (нарезка D-036) и docs-нарезку D-042 повторно не запускай после merge.

## Порядок

Задача N должна быть в `main` до старта N+1. Фичи 15–27 этот трек не блокируют и
им не мешают: при пересечении тех же Vue — rebase на `main`. `NuxtLink` не
добавлять (D-034); если фича 25 уже в `main`, существующий `NuxtLink` не
откатывать.

```text
docs (D-036…D-040, этот каталог)
  → 1  focus-visible
  → 2  иерархия заголовков + title индекса/404
  → 3  кабинет: статус в шапке
  → 4  кабинет: подписи полей
  → 5  кабинет: что дальше
  → 6  лента: текущий шаг
  → 7  лента на 390px
  → 8  спецификация на 390px
  → 9  файлы: жест «лист»
  → 10 лист файла: выписка
  → 11 тупик файла ≠ тупик заявки
  → 12 индекс: штамп не кнопка
docs (D-042…D-043)
  → 13 ссылки кабинета и листа в покое
  → 14 ссылки индекса в покое
  → 15 файлы: общая сетка
  → 16 лента: колонки на desktop
  → 17 лист: спека как в кабинете
  → 18 кабинет: колонка «Кол-во»
```

## Что сознательно не чиним

Зафиксировано в D-036 и D-042. Агент задачи N не «доделывает» этот список:

- оплату, чат, OTP, телефон, логин, кнопку «скачать», `href="#"`;
- ссылку с кабинета на служебный индекс `/`;
- переформулировку дисклеймера и подписи про мессенджер на `/`;
- API / OpenAPI / Prisma / seed / fixture-секреты;
- фичи 15–27 из `docs/remediation-plan.md`;
- glassmorphism, bento, неон, UI-kit, канбан, графики;
- смену D-014, Redis, `nuxt-security`, SWR/ISR на `/r/**`.

## Решения

D-036 (трек 1–12), D-037 (шапка кабинета), D-038 (лента), D-039 (лист и 404),
D-040 (хром: h1, title, focus; штамп — weight 400, не «кнопка»; куда вешать
класс — D-045), D-042 (трек 13–18 + оператор `реализуй`),
D-043 (`.document-link` и внутренняя сетка), D-044 (начертание ссылки в покое),
D-045 (штамп ≠ ссылка: индекс и текущий шаг ленты, `cursor: default`) —
`docs/decisions.md`. Исторические `task-12.md` / `task-14.md` оставляют плашку
`bg-accent/15` как вход того чата; живой канон после D-044/D-045 — не откатывать.
