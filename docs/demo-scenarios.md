# Сценарии демо

Ведущий поднимает показ через Makefile, когда цели есть: `make up` — полный стенд
web+api+postgres (D-016); `make dev` — Postgres из compose и api/web на хосте; `make restart`
— гасит контейнеры и leftover `node` на портах стенда (не Docker Desktop), затем снова `dev` (D-028). Канонический origin:
`http://localhost:3000`. Один стенд на машине для `:3000`/`:3001`.

## Счастливый путь (30 секунд)

1. Открыть `/`. Увидеть заголовок «Ссылки для показа», дисклеймер: список не для заказчика,
   подпись про мессенджер, инструкцию нажать строку.
2. В списке — сиды ПК «Нордщит» (номера, контрагенты, штампы статусов).
3. Клик по строке, например «КП готово» (З-10043) — переход на `/r/seed-z10043-quote-kuznetsov`
   без копирования ссылки.
4. Кабинет: «Статус заявки», фраза что менеджер прислал ссылку и вход не нужен, номер,
   контрагент, лента 1–4 с датами до «КП готово» и «ещё нет» на счёте, спецификация не-SKU,
   файлы как записи (у КП видны тип, размер, дата), дата обновления без второго штампа
   статуса. Клик по имени КП открывает HTML-лист документа; «К заявке» возвращает
   в кабинет. Скачивать нечего.
5. По желанию открыть другую ссылку (принят / счёт), чтобы показать разные шаги.

Зритель должен унести: «вот что увидит заказчик по ссылке».

## Битая ссылка

1. Открыть `/r/this-secret-does-not-exist` (или любой неизвестный секрет).
2. Понятный тупик на русском. Нет формы входа, телефона, OTP, «зарегистрироваться».
3. API на тот же секрет — 404 Problem Details.

## Не показывать

Рассылку писем, копирование ссылки как основной жест, админку статусов, каталог, чат.
